# מנוע ניטור – חוק הרווחים הכלואים (תיקון 277)

העובד הדיגיטלי "רווחים כלואים": מקבל את נתוני הלקוח, מחשב את שני המסלולים (סעיף 81 – תוספת מס 2%; סעיף 62א – רווחיות עודפת), ומחזיר סטטוס רמזור, סכומים לפעולה ודוח.

הקוד הוא תרגום אחד-לאחד של האקסל `לוגיקה חישובים לניטור רווחים כלואים מעודכן_1.xlsx` (גרסת 28.9.2026, אחרי אימות מול אברהם). כל נוסחה בקוד מסומנת בתא המקורי.

## התוכנה (פיילוט)

חלון מקומי כמו ממיין החשבוניות: פייתון מאחור, הממשק בחלון, הנתונים נשארים במשרד.

### התקנה במשרד (ווינדוס) – פעם אחת

**הדרך הקצרה:** להעביר את `install.bat` (מייל / דיסק-און-קי), לחיצה כפולה – מתקין פייתון וגיט אם חסרים, מושך את הקוד ל-`%USERPROFILE%\trapped-profits` ומפעיל. ידנית:

1. פייתון 3.10 ומעלה וגיט. הכי קל מ-cmd: `winget install -e --id Python.Python.3.12` ואז `winget install -e --id Git.Git` (או מהאתרים python.org – "Windows installer (64-bit)", ו-git-scm.com). לסגור ולפתוח cmd אחרי ההתקנה. `run.bat` עובד גם אם "Add to PATH" לא סומן (נופל ל-`py`). כרום/אדג' – לייצוא PDF.
2. לפתוח cmd ולהדביק:
   ```
   git clone https://github.com/NirLevi1/trapped-profits %USERPROFILE%\trapped-profits && cd %USERPROFILE%\trapped-profits && run.bat
   ```
3. לקריאת דוח שנתי **סרוק**: `winget install -e --id UB-Mannheim.TesseractOCR` (מק: `brew install tesseract`). קובצי השפה כבר בתיקייה `vendor/tessdata`. בלי זה – PDF דיגיטלי נקרא, סרוק לא.
4. מכאן: `run.bat` להפעלה (לחיצה כפולה), `update.bat` לעדכון מגיטהאב והפעלה מחדש. נתוני הלקוחות ב-`data\clients` לא נוגעים בעדכון. תקלות בהתקנה – `setup.log`.

מק: `run.command`. מפתחים:

```bash
pip install -r requirements.txt
python app.py            # פותח את החלון
build.bat                # (ווינדוס) בונה TrappedProfits.exe בתיקיית dist – לא לפיילוט
```

- לקוחות נשמרים ב-`data/clients/<ח.פ.>.json` ליד התוכנה (קלט + תוצאה + חותמת עדכון + סטטוס טיפול). הגדרות ודגלים ב-`data/clients/_settings.json`.
- שמירה בטופס = חישוב מיידי ועדכון תור העבודה.
- הממשק: `ui/_template.html` → `python ui/build_ui.py` מייצר את `ui/index.html` (לתוכנה) ואת `dashboard/index.html` (תצוגת דפדפן עם דמו). לערוך רק את התבנית.
- פתיחת `ui/index.html` ישירות בדפדפן עובדת כתצוגה (בלי מנוע).

### עדכונים מרחוק (ניר → אברהם)

1. ניר דוחף לגיטהאב (`git push`).
2. אצל אברהם, בכל הפעלה `run.bat` מושך את הגרסה האחרונה אם יש רשת (`git pull --ff-only`); בלי רשת – פשוט רץ.
3. גם בזמן שהתוכנה פתוחה: 4 שניות אחרי העלייה היא בודקת מול גיטהאב; אם יש גרסה חדשה – כרטיס כחול בתפריט "יש גרסה חדשה" ובהגדרות → עדכונים: "עדכון והפעלה מחדש" (מושך, סוגר, פותח).
4. `data/` לא בגיט – הנתונים לעולם לא נוגעים. שינוי לוגיקה מחשב מחדש את כל הלקוחות בעלייה (`recompute_all(only_outdated=True)`).
5. גישה: הריפו פרטי. לפני ההתקנה אצל אברהם ניר יוצר בגיטהאב **Fine-grained personal access token** – ריפו `trapped-profits` בלבד, הרשאה `Contents: Read-only`, תוקף שנה – ושם אותו ב-`install.bat` בשורה `set TOKEN=`. ההתקנה משכפלת עם הטוקן והמחשב של אברהם יכול למשוך עדכונים לבד. לבטל גישה = למחוק את הטוקן בגיטהאב.

## באגים ידועים באקסל (תוקנו בקוד)

שלושתם בתא **סימולטור!B20** ("המלצה תפעולית"):

1. `IF(מבנה!B9="לא", "החוק אינו חל"…)` – התא B9 ריק; התנאי לעולם לא מתקיים. הקוד בודק `מבנה!B13`.
2. `IF(חישוב_81!B19="כן", "עומדת בפטור"…)` – B19 מחזיר "פטור"/"לא", לעולם לא "כן"; לקוח פטור מקבל "תוספת המס זולה יותר". הקוד בודק `חישוב_81!B23`.
3. `IF(B10<B11, "מומלץ לשקול חלוקה"…)` – B11 ריק (ובכל מקרה משווה דיבידנד ברוטו למס). הקוד משווה מס דיבידנד על הפער (B14) מול תוספת המס (B15).

- **תרחיש ב׳ – גלגול 2024→2025.** המנוע מקבל נתוני בסיס לתום שנה קודמת; מאיפה הם באים (דוח סגור או גלגול) זה שלב קודם. `is_estimate=True` מסמן את התוצאה כאומדן.
- **קליטת מבנה אחיד / טבלת מיפוי חשבונות.** השלב הבא לפי התדריך.
- **דיבידנד רעיוני (126(ב)), סימולטור רשות המסים ל-62א** – מחוץ לתחולה, מסומנים לבדיקה ידנית.

## ניהול גרסאות לוגיקה

`LOGIC_VERSION` ב-`__init__.py` נשמר בכל תוצאה. שינוי בפרשנות (תשובת אברהם, חוזר חדש) = גרסה חדשה, כדי שאפשר יהיה להסביר בדיעבד לפי מה הופק מספר.
